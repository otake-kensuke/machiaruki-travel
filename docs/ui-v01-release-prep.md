## WARNの最小修正

`src/offline.js` の `observe()` は、監視しているWorkerがインストール完了状態（installed/activating/activated）へ到達したかを保持する。到達前にredundantとなる実インストール失敗だけを失敗扱いし、正常な交代によるredundantは失敗としない。アプリの準備状態は引き続き `SHELL_STATUS` で確認する。

`renderStatus()` の案内では、新版が待機中なら現在は開いている画面の版を使用中であることを表示する。初回未制御ページでも、準備完了は現在の画面の切替を意味せず、入力を保存して全アプリ画面を閉じ、開き直す必要があることを表示する。

`skipWaiting()`、`clients.claim()`、強制再読込は追加しない。`sw.js` は生成manifestのreleaseとoffline.jsのhashだけを更新し、Workerの処理本体は維持する。候補release：`1763b45fdbebb937b17c`、42アセット。

### 既存の旧画面に関する限界

すでに開いている公開旧版のページ内JavaScriptは、サーバー側の更新によって差し替えられない。旧版の初回未制御ページが実行中なら、旧判定による誤案内が再起動前まで残る可能性がある。これは修正版が読み込まれたページで再発することとは区別する。旧UIが残ること自体は待機設計に合致し、更新完了の判断には再起動後の新UIと準備完了の両方を用いる。
