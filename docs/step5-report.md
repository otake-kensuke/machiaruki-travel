# Step 5 実装報告

実施日：2026年10月18日（日本時間） / 基準コミット：`a2f0239`。

## 実装内容

旅行ホームに「バックアップを保存」「バックアップから復元」を追加しました。バックアップは選択中の旅行だけでなく、全旅行・日別・削除済みを含む予定・交通・宿泊・訪問記録の6配列を含みます。既存ID、作成/更新日時、参照、GPS情報を保持し、kind=backup、schemaVersion=1.0、exportedAtを付けます。

JSON Fileのダウンロードと、ファイル共有対応端末での共有出力を実装しました。iPhoneでは共有先の「ファイルに保存」を利用する想定です。共有APIは準備済みFileをクリック内で直接渡し、非対応時はダウンロードを使用します。共有キャンセル時に自動で別方式へ切り替えません。

ホームに最終出力操作日時を表示します。ダウンロード要求・共有への受渡しと保存完了を区別し、端末外への保存も未確認と明示します。出力後に保存データが変わっていれば再出力を案内します。

復元は通常の旅程追加と分離しました。JSON全件検証後に現在の置換対象と復元後の全旅行名・日程・件数を表示します。現在データの退避JSONと端末内退避情報を準備し、出力操作が成功した後、利用者による保存先での確認と全件置換の2つの明示確認を必須にします。アプリから保存先への永続化完了は確認できないため、保存済みとは断定しません。

最終復元時も同じreadwriteトランザクション内で最新データ・退避準備ID・出力記録を照合します。別タブ更新や別の復元準備を検出すれば停止します。直前の復元前コピーの保持、activeの一括置換、準備情報の削除を同時に行い、oncomplete後だけ成功表示します。書込途中の失敗では全キーを巻き戻し、入力内容を保持します。

DB構造バージョン1、既存データモデル、schemaVersion 1.0を維持し、workspaceストアの追加キーで管理します。起動時の初期化・サンプル自動挿入はありません。直前の復元前データは1世代だけ端末内にも残し、出力画面から再取得できます。

## 残課題

- iPhone実機のSafari/ホーム画面からのJSON共有・ダウンロード・「ファイル」で開く操作・退避確認・復元は未検証。共有はモックによる成功/キャンセル/失敗を検証済みですが、ネイティブ画面の検証は別途必要です。
- 実機GPSの許可・精度、ホーム画面とSafariの保存領域、VoiceOverやソフトウェアキーボードは未検証です。
- Service Workerとオフライン起動/更新制御は次段階。今回登録・実装していません。
- 同じブラウザ内の退避コピーもデータ削除で失われます。外部ファイルの保存成功はアプリから証明できないため、旅行中は利用者が保存先でJSONを確認してください。
- 出力・復元は20 MiBまで対応。自動マージ・部分復元・クラウド保存は範囲外です。
