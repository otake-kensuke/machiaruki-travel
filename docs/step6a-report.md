# Step 6A オフライン対応 実装報告

実施日：2026年10月18日（日本時間） / 基準コミット：`a350c8a`。

## 実装内容

初回オンラインでアプリ本体の必要33ファイルをService WorkerのCache Storageへ準備します。保存済み旅程がある同じURL・同じ保存領域であれば、次回以降のオフライン起動、3画面の閲覧、予定編集、訪問記録、IndexedDB保存、JSONバックアップ/復元を利用できます。サンプルJSONも同梱ファイルとしてキャッシュしますが、データへの追加は引き続き利用者の明示操作のみです。

画面上部に準備中/準備完了/失敗/新版待機、接続状態、再確認ボタンを表示します。navigator.onLineは通信成功の保証ではないと表示します。GPSは従来の単発取得を維持し、通信断や測位失敗時も座標なしで保存できます。Googleマップの各操作付近と案内欄にオンライン依存を明記しました。

旅行データのモデル・schemaVersion 1.0・IndexedDB構造バージョン1と既存の保存APIは変更していません。Service WorkerはIndexedDBを読み書きせず、既存データの初期化・サンプル挿入・外部送信を行いません。個人のJSONやGoogleマップはキャッシュ対象外です。

## 版の整合性と更新手順

- 開発用スクリプトがアセットのSHA-256とworker本体から版を生成し、sw.jsへ一覧を埋め込みます。テキストはCRLFをLFに正規化して、WindowsチェックアウトとGitHub配信の改行差を許容します。実行時にビルドは不要です。
- installで全ファイルをHTTPキャッシュに依存せず取得し、内容hashを照合してから保存します。取得失敗・hash不一致・保存失敗なら新版を有効化せず、その版のキャッシュを除去します。改行差だけで同じ内容の版が再インストールされる場合は、既存の完全なキャッシュを再利用し、通信失敗で稼働中のコピーを削除しません。
- 既存workerが制御するページは、HTML/CSS/JSを常にその版のキャッシュから読みます。ネットワークから未検証の別版コードを補充しません。rootとindex.htmlは同じ入口として扱い、query/hashの有無で別版へ分岐しません。
- skipWaiting/clients.claimは使いません。新版は待機し、入力を保存してアプリの全タブ・ウィンドウを閉じて開き直すよう案内します。1タブの再読込だけでは切替わらない場合があります。更新のための強制再読込はありません。
- 新版activate後に、そのscopeの旧版キャッシュだけを除去します。キャッシュ名にアプリ名・scopeの完全URL・版を含め、他アプリや別サブディレクトリを除去しません。
- `updateViaCache: none` でworkerの更新を確認します。初回の成功前は準備完了と言いません。初回失敗後は再登録して準備し直せます。

アプリ本体/同梱アセット/sw.jsの変更後は、以下を実行し、sw.jsも同時にコミットしてください。テストが生成物とコードの一致、モジュール・HTML・マニフェストの依存先を検査します。

```powershell
node scripts/update-shell.mjs
node scripts/update-shell.mjs --check
node --test tests/model.test.js tests/step3.test.js tests/step4.test.js tests/step5.test.js tests/step6a.test.js
```

## キャッシュが消えた場合

開いているアプリでは「準備・更新を再確認」で現在版を検証し直して再準備します。キャッシュ全体がなく、通常のアプリが起動できない場合は、必要モジュールに依存しない再準備画面をworkerが返します。オンラインで同じ版を取得できれば回復します。新版が待機していれば全タブ終了による更新を案内します。古い版のファイルがサーバーにない場合、別版を混ぜて起動させません。

キャッシュだけの消失時にIndexedDBは触りません。ただし、OS/ブラウザが保存領域全体を削除した場合のデータ保持は保証できません。JSONの外部ファイル保存は引き続き必要です。

## 残課題

- iPhone Safari・ホーム画面での機内モード起動、OS終了後の保存、実機GPS、ファイル共有/保存/復元、VoiceOverは未検証です。PCのモバイル幅確認は実機検証ではありません。
- Safariとホーム画面版の保存領域やアプリ終了の扱いは実機で確認が必要です。準備完了後に、その起動方法のまま通信断の一連操作を試してください。
- 初回オンライン準備に失敗した場合、またはOSがキャッシュを除去した場合はオフライン起動できません。オンライン再準備または新版への更新が必要です。
- 強制更新はしないため、旧版のタブが残っている間は新版が待機します。入力保存後の全ウィンドウ終了が必要です。

Private管理を維持します。GitHub Pages公開、Public変更、外部デプロイは行いません。mainへのコミット/pushとリモート一致は完了報告に記載します。

参考仕様：[Service Workerのライフサイクル](https://web.dev/articles/service-worker-lifecycle)、[更新と待機](https://web.dev/learn/pwa/update)、[updateViaCache](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerRegistration/updateViaCache)。既存ページと別版workerの混在を避けるため、標準の待機を維持しています。
