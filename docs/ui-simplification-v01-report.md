## UI-01〜UI-06

### UI-01

イラスト下のfigcaptionを描画しない。背景・3人・画像選択・タイトルを維持。汎用背景も同じ方針。画像ファイルとbrand.jsは変更していない。

### UI-02

実装前に提案した「原文を切り捨てず、登録内容から概要を表示する」方式を採用。

- 1行目: 日数・削除済みを除く予定件数。
- 2行目: 交通件数・宿泊件数。
- 特定の旅行名や予約内容を固定せず、既存データから導出。旅行名・期間を維持。
- trip.memoを削除/書換え/文字数切り捨てしない。短い原文を抽出して意味を変えることもしない。
- 通常のiPhone相当幅で2行。文字拡大時には欠けを防ぐ自然な折返しを優先し、高さ制限や省略記号で隠さない。

### UI-03

最大4件・残件数・日付選択・「予定と記録をひらく」は基準版に既にあるため、そのまま維持して確認した。

開始日時順、同時刻はorder順、時刻未設定は末尾というhomeSummaryのルールを変更しない。予定0/1/4/5件、複数の時刻未設定、同時刻、長い予定名を追加確認。

### UI-04

予定時刻・分類・名称・既存操作・関連訪問の表示と編集を維持。住所の従来表示も保持。

メモはdetails/summary「詳細メモ」を初期状態で閉じる。開くと元の全文を改行付きで表示し、HTMLとして解釈しない。空文字・空白だけのメモは開閉UIを出さない。訪問自身のメモと操作は従来どおり表示する。

**予約状態の判断:** 現行モデルには正式に定義・検証された予約状態フィールドがない。memoや未知フィールドからバッジを推測しない。「未予約」「予約確定ではない」「予約確定後に取消」だけでなく、自由文の確定表記も自動判定しない。予約・雨天・注意の原文は詳細メモに残る。

### UI-05

標準HTMLの開閉要素を使用。summaryは44px以上。Enter/Space、長い日本語/英字の名称、320/393/430px、文字200%、メモを開いた状態の折返しとデータ/順序不変を検証。VoiceOver実機は未検証。

### UI-06

ダウンロード・共有を同じsecondaryボタンにし、それぞれの直下に短い説明を配置。

出力処理run、canShare判定、利用者操作内での共有開始、ファイル名、JSON、出力履歴、共有非対応時の表示、直前退避の再出力の意味を変更していない。復元画面・退避/確認フローは変更していない。
