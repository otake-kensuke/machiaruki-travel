# 街歩きラボ｜旅行ノート v0.1

北海道旅行（2026年10月30日〜）での試用を目指す、端末保存型の静的Webアプリ。Step 1〜4を実装済みです。GitHub Pages公開・デプロイは行っていません。

## ローカル起動

Node.js 20以降で、プロジェクトフォルダーから実行します。インストール・ビルドは不要です。

```powershell
node scripts/serve.mjs
```

ブラウザで `http://127.0.0.1:4173/` を開きます。初回は空です。「サンプル旅程を読み込む」→内容確認→「この端末に読み込む」で追加してください。`index.html` を直接ファイルとして開く方法はサポートしません。

- サーバーは127.0.0.1にのみ待ち受けます。終了はCtrl+C。
- 別ポートはPowerShellで `$env:PORT = '4174'` を指定してから起動します。
- `http://127.0.0.1:4173/machiaruki-travel/` はGitHub Pages相当のサブパス確認用です。
- ローカルURLを変えると別の保存領域になります。データはサーバー上のファイルではなく、ブラウザのIndexedDBに保存されます。

## 今回実装したこと

- 下部タブによる3画面の移動、旅行ホームの日程・交通・宿泊、日付別の予定と実績、日別訪問履歴。
- 明示操作によるサンプル全件追加。3日分、8予定、2交通、2宿泊、2仮訪問。
- IndexedDBの保存基盤。起動時は読み込みのみ、追加時は全件検証と一括トランザクション。
- 重複IDの拒否、複数タブの並行追加、保存失敗時のエラー・確認画面保持。
- 保存データの未知形式を初期化せず停止。既存データの自動上書き・削除機能はありません。
- 旅行が複数ある場合の選択欄。通常の画面操作で旅行を新規作成する機能は未実装です。
- ホーム画面向けマニフェスト、PNGアイコン、セーフエリアに配慮したレイアウト。
- 旅行ホームから旅程JSONを選択し、旅行名・期間・日別/予定/交通/宿泊の件数を確認して追加。
- 不正なJSON、未対応バージョン、バックアップ形式、既存ID衝突は保存せず拒否。取込の自動マージは行いません。
- 日別予定画面から予定の追加・編集・確認付き削除。IDと作成日時を保持し、訪問記録は変更しません。
- 別タブで同じ予定を変更した場合は上書きせずエラー。入力内容を残し、最新データの開き直しを案内。
- 予定からの訪問・予定外の訪問を、内容確認後に保存。記録開始時だけ単発GPSを取得します。
- GPS拒否・失敗・タイムアウトでも座標なしで保存。GPS待ちでも入力・確認を進められます。
- 訪問日時・施設名・住所・メモの編集、同じ場所への複数訪問、予定削除後の履歴保持。
- 保存した地点または施設名・住所を使うGoogleマップの外部リンク。地図APIキーは使いません。

サンプルはすべて仮の設定で、予約情報や実際の訪問実績ではありません。仮訪問を含むため、サンプルJSONの外枠は `kind: "backup"` です。このボタンはアプリ同梱サンプルを追加する機能であり、利用者のバックアップファイルを復元する機能ではありません。

## 保存の方針

DB名は `machiaruki-travel`、DB構造バージョンは `1`。`workspace` ストアの `active` キーに、データ・スキーマバージョン・リビジョンをまとめて保存します。v0.1の小規模な旅程では、この構造でコレクション間の整合性を保ちます。

readwriteトランザクション内で最新データを取得し、追加・編集・削除済み設定を検証して保存します。成功は `transaction.oncomplete` 後に返します。サンプルは起動時に挿入しません。画面が再び表示されたときはDBを再読込します。予定の削除は内部の削除済みフラグで行い、参照先と訪問記録を残します。

端末保存は永久保存を保証しません。ブラウザデータを削除しないでください。バックアップが未実装の現在は、実旅行の記録を投入する段階ではありません。アプリから旅行データを自動送信せず、アクセス解析も行いません。Googleマップのリンクを押した場合のみ、その記録の座標または施設名・住所をGoogleへ渡します。

## 検証

データモデルのテスト（追加インストール不要）：

```powershell
node --test tests/model.test.js tests/step3.test.js tests/step4.test.js
```

ブラウザの統合テストは、起動済みサーバーとPlaywright、Microsoft Edgeが必要です。Playwrightが解決できる環境なら：

```powershell
node tests/browser.mjs
node tests/step3-browser.mjs
node tests/step4-browser.mjs
```

別の場所にPlaywrightがある場合は、その `index.mjs` の絶対パスを `PLAYWRIGHT_MODULE` に指定してください。`BROWSER_CHANNEL`（既定 `msedge`）と `TEST_BASE_URL`（既定 `http://127.0.0.1:4173/`）も指定できます。テストは独立したブラウザコンテキストを使い、利用者の通常プロファイルには接続しません。スクリーンショットは無視対象の `test-results/` に出力します。

## 旅程JSONの取込と予定編集

1. 旅行ホームの「旅程JSONを取り込む」を押し、`kind: "itinerary"` のJSON（2 MiB以下）を選択します。
2. 検証に成功すると、旅行名・期間・件数を表示します。この時点では保存されません。
3. 「確認して追加する」で新しい旅行として追加します。保存時にも最新データとのID衝突を検査します。
4. 「予定・記録」から日付を選び、「＋ 予定を追加」または各予定の「編集」「削除」を押します。

施設名・日付・時刻（空欄可）・分類・住所・メモを入力できます。日付は旅行期間内、時刻は旅行に設定したタイムゾーンです。日付を変えても実際の訪問日時は変わりません。入力先の日別データがない場合は同じトランザクションで作成します。予定地点はJSONからの値を維持し、座標編集は現段階の入力画面に含めません。

旅程の書式は [データ仕様](docs/data-format.md)、完全な例は `samples/hokkaido-2026.itinerary.json` を参照してください。この例は同梱サンプルと同じIDを使うため、サンプル読込済みなら衝突として拒否します。既存の旅行を更新するための再取込は対応せず、予定の変更は画面上で行います。

## 訪問記録と地点の確認

1. 予定カードの「訪問を記録」、または「＋ 訪問記録を追加」を押します。新規記録の訪問日時は記録開始時の現在時刻です。予定の日付・時刻には置き換えません。
2. GPS取得中も施設名・住所・日時・メモを入力できます。GPSが使えなくても座標なしで確認できます。
3. 「内容を確認」→「この内容で保存」で保存します。「内容を修正」で入力へ戻れます。確認時に地点を固定し、その後に届いたGPS結果は反映しません。
4. 予定内の実績、または振り返りの各記録から「訪問記録を編集」を押すと、日時・施設名・住所・メモを修正できます。編集時はGPSを取得せず、元の地点・精度・取得日時・予定への参照を維持します。
5. Googleマップのボタンは、座標があれば保存地点を開き、なければ施設名・住所で検索します。GPSだけで施設名は確定しません。

GPSの取得待ちは最大12秒で表示を切り替えます。許可拒否や取得失敗時は、明示的に「GPSを再取得」することもできます。ブラウザの単発APIには中断機能がないため、閉じる・確認・再取得後に届く古い結果を無視します。常時追跡はしません。

実際の訪問日は旅行期間外でも記録でき、該当日の予定がなくても日付切替と振り返りに表示します。同じ場所・同じ予定への複数訪問は独立した記録です。住所は訪問記録側の文字列として保持し、後から予定の住所が変わっても検索内容を勝手に変更しません。

ブラウザ検証の位置情報は合成座標を使用しています。実際のiPhone GPS・Safariの許可画面・Googleマップアプリとの往復は実機での確認が必要です。
